Data Acquisition

Pull organization records from two major databases using hundreds of climate-focused search terms.

Crunchbase Candid 500K+ Records
Input: Climate search terms & API credentials → Output: Raw organization files
📊
Crunchbase Data Pull
+

Queries the Crunchbase API using 500+ curated climate search terms to retrieve venture-backed companies and startups. Filters to company entities only (excluding pure investor profiles).

Data Files Queried Organizations, Funding Rounds, Founders, Investors
Key Fields Name, funding, sectors, employee count, website, founders
Funding Detail Round-by-round history from 2010 onward, investor identities
Special Flags Government funders, diversity spotlights, IPO status
🏛
Candid Data Pull
+

Ingests nonprofit and philanthropic organization data from Candid (formerly Foundation Center / GuideStar). Includes grant data, 990 tax filings, board and personnel records, and program descriptions.

Data Files Main data, funders, personnel, programs, 990 filings
Min. Funding $20,000 threshold
Special Processing Government funder identification via metadata; ALL CAPS text normalization from 990 filings
🔍
Climate Search Terms
+

A curated and expanded set of approximately 500 climate-related search terms, updated quarterly. These terms drive the initial Crunchbase query and are later used for keyword tagging.

Term Count ~500 expanded terms
Update Cycle Quarterly (e.g., 2025 Q2)

Data Preparation & Combination

Clean, standardize, and merge both data sources into a single unified dataset.

Standardization Deduplication
Input: Raw CB + Candid files → Output: Combined dataset (~500K records)
⚙
Crunchbase Cleaning
+

Filters to company entities and processes raw Crunchbase data. Maps employee enum codes to human-readable ranges, extracts chronological funding-by-year data, and identifies government-backed organizations.

  • Filter to companies founded or funded after 2010
  • Map employee enums (e.g., c_00001_00010 → "1-10")
  • Organize funding rounds chronologically and by type
  • Flag government funders based on investor metadata
  • Deduce org type (for-profit vs non-profit) from context
⚙
Candid Cleaning
+

Processes Candid nonprofit data, identifying government funders, applying minimum funding thresholds, normalizing text casing from IRS 990 filings, and standardizing columns to match the Crunchbase schema.

  • Identify government funders via gm_type / funder_type metadata
  • Add funding-by-year from separate Candid metadata
  • Filter: minimum total funding of $20,000
  • Normalize ALL CAPS text from 990 filing descriptions
🔀
Combine & Deduplicate
+

Merges both datasets into a single dataframe. Removes exact duplicates, standardizes org types and funding stages, and classifies funding as Philanthropy or Venture. Optionally tags each organization with matched search terms.

Dedup Key (id, Data Source) tuple
Standardization Org type, funding stage, sector, industry
Search Term Tagging Matches org text fields against expanded search terms; creates master term mappings
3

Text Enrichment

Fill gaps in organization descriptions by scraping websites and LinkedIn profiles.

CoreSignal API Web Scraping PostgreSQL Cache
Input: Combined dataset (many short descriptions) → Output: Text-enriched dataset
🌐
Website Scraping & Summarization
+

Identifies organizations with descriptions shorter than 100 characters and scrapes their websites to extract richer content. Uses Playwright for rendering JavaScript-heavy sites. An LLM then summarizes the scraped content into concise descriptions.

Threshold < 100 character descriptions
Scraping Tool Playwright (headless browser)
Pages Scraped Home page + "About" subpages
Caching PostgreSQL (avoids re-scraping)
💼
LinkedIn Data Integration
+

Retrieves structured company profile data from LinkedIn via the CoreSignal API. Extracts employee counts, specialties, industry classification, logo URLs, and "About" text. Merges on normalized LinkedIn URL, handling variations in http/https and trailing slashes.

API Provider CoreSignal
Fields Extracted Employee count, specialties, about, logo, industry
Merge Logic Robust LinkedIn URL normalization; employee range mapping from LI to CB format; sector and industry deduplication
🧹
Text Processing & Validation
+

Combines all available text fields (Description, 990 Filing, Website Summary, LinkedIn About) into unified text representations. Cleans whitespace, line breaks, and encoding issues. Validates that each organization has sufficient text coverage for downstream models.

4

Climate Relevance Filtering

The critical gate: a fine-tuned AI model identifies the ~7% of organizations that are truly climate-relevant.

Fine-tuned GPT-4o-mini 500K → 33K
Input: ~500K organizations with enriched text → Output: ~33K climate-relevant organizations
🤖
Relevance Classification Model
+

A fine-tuned GPT-4o-mini model acts as a climate change expert, reading each organization's combined text and making a binary determination: climate-relevant (1) or irrelevant (0). Each prediction includes a probability score for confidence tracking.

Model Fine-tuned GPT-4o-mini
System Prompt "You are a climate change expert."
Output Binary (0/1) + probability score
Approach Conservative (precision over recall)
✅
Quality Control & Overrides
+

A manual label override mechanism allows human experts to correct known misclassifications. Results are cached in a database to avoid reprocessing on subsequent pipeline runs.

  • Label override file for post-hoc corrections
  • Results cached in database for efficiency
  • All predictions saved (including filtered orgs) for audit
🎯
Filtering Results
+

Only organizations classified as climate-relevant (prediction = 1) proceed to the enrichment stages. This is the single largest data reduction step, removing approximately 93% of records.

Input ~500,000 organizations
Output ~33,000 organizations
Reduction ~93% of records filtered out
Saved Full prediction results (including filtered) for audit
5

AI-Powered Classification

Classify organizations by climate strategy, entity type, and generate unified summaries.

ClimateBERT AdaBoost Ensemble GPT-4o-mini
Input: ~33K climate-relevant orgs → Output: Classified orgs with unified summaries
🌡
Adaptation vs. Mitigation Classification
+

A ClimateBERT-based model, hosted on Baseten, classifies each organization's climate focus into one of three categories: Adaptation (adapting to climate impacts), Mitigation (reducing emissions), or Both. Organizations that don't fit any category are removed.

Model ClimateBERT (CPI 2024)
Hosting Baseten API
Categories Adaptation, Mitigation, Both
Processing Batched inference with caching
🏢
Organization Type Classification
+

An AdaBoost ensemble classifier predicts whether each organization is For-Profit or Non-Profit. It combines TF-IDF text features with category encodings from LinkedIn industry and Crunchbase sectors. Heuristic overrides handle edge cases (e.g., venture-funded orgs forced to for-profit).

Model AdaBoost ensemble
Features TF-IDF (1-3 n-grams) + category encoding
Override Rules Venture funding → For-Profit; LinkedIn "Non-Profit" → Non-Profit
📝
Summary Generation
+

Synthesizes all available text (original description, 990 filings, website summary, LinkedIn about) into a single unified description of 4-5 sentences using GPT-4o-mini. This "summary of summaries" becomes the canonical description used throughout the platform.

Model GPT-4o-mini
Output Length 4-5 sentence paragraph
Text Sources Combined Description, 990 Filing Description, Website Summary, LinkedIn About
6

Taxonomy Mapping

Map each organization to the One Earth Solutions taxonomy using embeddings, semantic similarity, and few-shot classification.

OpenAI Embeddings Cosine Similarity Few-Shot LLM
Input: Classified orgs + taxonomy definitions → Output: Hierarchical solution category assignments
🧠
Text Embedding Generation
+

Generates dense vector representations (embeddings) for every organization's text and every taxonomy term definition. Uses OpenAI's text-embedding-3-large model (3,072 dimensions). All embeddings are cached in PostgreSQL for reuse across pipeline runs.

Embedding Model text-embedding-3-large
Dimensions 3,072
Items Embedded ~33K org texts + ~250 taxonomy terms
Caching PostgreSQL embedding cache
📐
Semantic Similarity Matching
+

Computes cosine similarity between each organization embedding and every taxonomy term embedding. Uses percentile-based ranking rather than raw scores, making the matching position-independent and more robust. A few-shot LLM classifier refines edge cases where similarity scores are ambiguous.

Method Cosine similarity matrix
Ranking Percentile-based (position-independent)
Refinement Few-shot LLM classification validates and adjusts ambiguous matches
🌳
One Earth Solutions Taxonomy
+

The primary taxonomy is the One Earth Solutions framework, a 4-level hierarchy of ~250 climate solution categories. Each organization is mapped to its most relevant categories at every level of the hierarchy.

Level 0 (Pillar) e.g., Energy Transition
Level 1 (Sub-Pillar) e.g., Renewable Power
Level 2 (Solution) e.g., Advanced Nuclear
Level 3 (Term) e.g., Small Modular Reactors
⚠
False Solutions & Levers of Change
+

Two additional taxonomy layers are applied: False Solutions flags potentially harmful or misleading approaches (greenwashing), and Levers of Change categorizes the implementation strategies organizations use to create impact (e.g., policy, technology, finance).

💰
Funding Distribution
+

Each organization's funding is fractionally distributed across its matched taxonomy categories based on match confidence scores. This enables aggregate analysis of funding flows by solution area, redistributed hierarchically across all taxonomy levels.

Method Fractional distribution by match confidence
Redistribution Hierarchical across all taxonomy levels
7

Tagging & Geography

Extract climate keywords, geographic mentions, and diversity indicators from every organization.

N-gram Matching LLM Geotagging Google Geocoding
Input: Taxonomy-mapped organizations → Output: Fully tagged & geolocated orgs
🏷
Climate Keyword Extraction
+

Scans all text fields using n-gram matching (unigrams through trigrams) against a curated climate keyword taxonomy. Weights each tag by frequency and importance. Separates tags into distinct categories for different analysis needs.

Method N-gram matching (1-3 grams)
Tag Source Curated keyword taxonomy (~150 terms)

Tag categories produced:

  • Main climate tags (energy, sustainability, renewable, etc.)
  • Equity & Justice tags (justice, indigenous, low income, etc.)
  • Approach / Strategy tags (technology, policy, finance, etc.)
  • Underserved Community keywords
🌍
Geographic Tagging
+

Uses an LLM with optimized prompting to extract geographic entities (countries, states, cities) mentioned in organization descriptions. Produces both flat tag lists and structured location dictionaries for mapping.

Method LLM-based extraction (GPT-4.1-mini)
Output Format {city, state_region, country}
📍
HQ Geocoding
+

Geocodes each organization's headquarters address to latitude/longitude coordinates using the Google Geocoding API. Parsed addresses are cleaned and validated to produce standardized City, State, and Country fields.

🤝
Diversity & Equity Tags
+

Consolidates diversity data from Crunchbase spotlights into standardized tags. Maps founder demographics (Women, Black, Latine, South Asian, East Asian, Southeast Asian, MENA, Indigenous) and produces summary flags for BIPOC representation, equity/justice mentions, and underserved community focus.

JSON Excel Network Viz
Input: Fully enriched dataset → Output: Platform-ready files & visualizations

Data Export
+

The enriched dataset is exported in multiple formats for different consumers. The primary output includes the full organization records, along with separate files for taxonomy mapping results, relevance model scores, and funding distribution data.

Primary Output cb_cd_li_meta.json / .xlsx
Records ~33,000+ organizations
Fields per Record 150+ enriched columns
Supplementary Files Taxonomy mappings, relevance scores, funding distributions
🕸
Network Visualization
+

Organizations are connected into a tag-co-occurrence network graph. Community detection (Louvain clustering) identifies natural groupings. The network is laid out using force-directed or UMAP algorithms, producing an interactive visualization for the platform.

Graph Type Tag co-occurrence network
Clustering Louvain community detection
Layouts Force-directed, UMAP, t-SNE
Viewer Interactive MapPR player
📊
Final Dataset Schema
+

The final dataset contains 150+ columns organized into major field groups:

  • Identity: Name, ID, source, URLs, logo
  • Funding: Total funding, stage, by-year breakdown, investors, donors
  • Classification: Org type, adaptation/mitigation, climate relevance score
  • Taxonomy: One Earth categories at 4 hierarchy levels, false solutions, levers
  • Text: Original description, website summary, LinkedIn about, unified summary
  • Tags: Climate keywords, equity/justice, approach, underserved communities
  • Geography: HQ coordinates, geo tags, city/state/country
  • People: Founders, executives, board, employee count, diversity tags

What Powers the Pipeline

A multi-model architecture with aggressive caching ensures scalability, quality, and cost efficiency across every run.

AI & ML Models

Fine-tuned GPT-4o-mini for relevance, ClimateBERT for adaptation/mitigation, AdaBoost for org type, OpenAI embeddings for taxonomy, few-shot LLM for refinement.

5 Models

External APIs

Crunchbase for venture data, Candid for philanthropy, CoreSignal for LinkedIn, Google for geocoding, OpenAI for embeddings & classification.

5 APIs

Caching Layer

PostgreSQL-backed caching for embeddings, LLM responses, web scraping, and LinkedIn data. Dramatically reduces cost and runtime on subsequent pipeline runs.
